# HULOG — codebase guide

React/TypeScript/Vite digital film props with a Node/Socket.IO production server. All personal, financial, messaging, permissions and camera interfaces are fictional simulations.

## Architecture
- `src/data/production.ts`: editable master configuration, exact screenplay text, six scenes, cues, documents.
- `src/shared/model.ts`: shared types, validation and deterministic device reducer.
- `server/sessions.ts`: session ownership, device role registration and authoritative state.
- `server/index.ts`: HTTP/static hosting and Socket.IO transport; capability tokens protect director actions.
- `src/services/`: persistence, audio, exports, connection.
- `src/components/`: production controls and shared actor surfaces.
- `src/App.tsx`: director, display, editor and documents routes.
- `src/styles.css`: responsive production UI and fictional device styles.
- `public/sw.js`: offline app shell caching.
- `tests/`: reducer, transport and browser acceptance tests.

## Commands
`npm install`; `npm run dev` (Vite 5173, socket server 3001); `npm run build`; `npm start` (built app and sockets on 3001); `npm test`; `npm run test:browser`.

## Invariants
Actor displays preserve their last state on disconnection. Server owns cue timers, and STOP clears every queued action. Actor input can update only its assigned device. Control token must never be included in actor join links. Session role names must be unique. No actual SMS/calls/contact/location/photo access. Unsent MAMA message has no send operation. Black display cannot be awakened by actor taps. All edits must update this guide.

## Deployment
Requires a persistent Node process with WebSocket support; static hosting alone cannot provide synchronization. LAN filming needs reachable port 5173 (development) or 3001 (production). HTTPS or localhost is required for service workers and wake lock. Sessions persist in server memory through client reconnects, not server restarts; export continuity snapshots for recovery.

## Implementation and validation notes
- Project initialized from an empty workspace. `public/sample-production.json` provides a portable six-scene sample; runtime master defaults are in `src/data/production.ts`.
- Browser credentials are origin-local; use separate profiles for multiple test devices. Director tokens never appear in broadcast state or exports.
- Built offline cache is generated by `scripts/build-offline.mjs` from hashed assets; development does not install the worker. HTTP LAN use supports sockets but not secure-context APIs.
- Native camera is intentionally not used; the camera prop is simulated. All financial exports are fictional and PDF pages are rasterized at 2× resolution.
- Browser suite uses installed Chrome by default and both a Vite server (5173) and built production server (4173). Core integration tests start an ephemeral local socket server.
- Dependency audit after upgrading jsPDF and Zod reports zero vulnerabilities. Core tests and initial browser workflows passed; expanded offline/export/laptop suite is included.
- Settings have validated bounds; screen illumination defaults off and is capped at 15%; overload interval is at least 500 ms.
- Rehearsal/live-take labels never mutate master cues; runtime state and configuration are separate. Continuity restore validates complete device states before applying.
- Node/WebSocket hosting is required. No static-only hosted deployment was attempted because it would omit the required synchronization server.
